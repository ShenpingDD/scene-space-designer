# 设计决策记录（说明页）

代码注释与文档正文里，常能看到「**设计决策记录**」这个词，例如：

- `// 单位口径见设计决策记录：文件 m，声明/bbox mm`
- `三条铁律（都来自设计决策记录，不是这里现编的）`

它指的是本项目**内部的设计决策留档**（ADR 形式：一条决策一段，含背景、取舍、被推翻的旧方案）。
这份留档**不随公开仓发布** —— 它包含现场部署与验收过程，属于内部材料。

## 那为什么代码里还要引用它

因为**判据与阈值的来历**是这套代码最容易被改坏的地方：
「为什么门净空要 106°」「为什么阈值是这几个数」「为什么贴图只留 2 张」——
这些数字背后都是踩过的坑。留一句「见设计决策记录」，是提醒后来的人：
**这些数不是拍脑袋拍的，别顺手改**。

## 读不到那份留档时怎么办

公开仓把结论本身都写进随附的文档了，按主题找即可：

| 想知道 | 看 |
| --- | --- |
| 分层、目录、数据为什么这么切 | [`ARCHITECTURE.md`](ARCHITECTURE.md) |
| 判据、参数表、门语义、净空怎么算 | [`KERNEL.md`](KERNEL.md) |
| 模型怎么量、门几何怎么测 | [`MODEL-PIPELINE.md`](MODEL-PIPELINE.md) |
| 界面规范、角标、文案口径 | [`UI-SPEC.md`](UI-SPEC.md) |
| 起停、排障、验收、迁移 | [`RUNBOOK.md`](RUNBOOK.md) |
| 改哪里、怎么验、提交纪律 | [`DEVELOPMENT.md`](DEVELOPMENT.md) |

一句话：**引用它是因为「为什么」重要，而不是因为它可点开**。
